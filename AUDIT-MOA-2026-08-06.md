## P0 — Must Fix Before Next Release

### P0-1: Use-After-Free in `pty_output_poller()` after IPC "signal Kill"

**File:** `bs_mesh.hpp:3649 → 4304`
**Evidence:** `dispatch_ipc_json("signal", {type:"Kill"})` calls `sessions_.kill()` which erases the Session. But any `Conn` with `attached_session` pointing to it is never cleared. Next event loop tick, `pty_output_poller()` dereferences the dangling pointer.
**Impact:** Crash or memory corruption. Triggers reliably on `ctl signal <session> Kill` while a peer is attached.
**Fix:** Before kill, null out attached_session pointers:
```cpp
for (auto& c : conns_)
    if (c.attached_session == s) c.attached_session = nullptr;
sessions_.kill(session_name);
```

## P1 — Security & Reliability

### P1-1: Command Injection via EDITOR + Peer-Supplied File Path
**File:** `bs_mesh.hpp:5653-5660`
**Evidence:** `system(editor + " " + local_path)` — `local_path` comes from peer's FileMeta filename field. Unquoted on POSIX, escapable on Windows.
**Fix:** Use `execvp` with argument array instead of `system()`.

### P1-2: DNS Resolution Blocks Event Loop
**File:** `bs_mesh.hpp:1152-1160`
**Evidence:** `gethostbyname()` is blocking with no timeout. A bad seed hostname freezes all peer I/O for 30-75s.
**Fix:** Replace with `getaddrinfo()` + async resolution or pre-resolve seeds to IPs at startup.

### P1-3: TOFU First-Connect MITM
**File:** `bs_mesh.hpp:1219-1222`
**Evidence:** First connection pins whatever key is presented. MITM on first connect = permanent compromise. Amplified by mDNS auto-discovery on untrusted LANs.
**Fix:** Document as explicit limitation. For high-security: require `seed ... pubkey=` hard-pin. Consider interactive confirmation on first connect.

### P1-4: Windows Named Pipe IPC Has No Per-User Auth
**File:** `bs_mesh.hpp:704-716`
**Evidence:** `PIPE_REJECT_REMOTE_CLIENTS` blocks network clients only. Any local user can connect and issue IPC commands (list sessions, kill sessions, trigger file transfers).
**Fix:** Build a DACL from current process token SID. Pass as `lpSecurityAttributes` to `CreateNamedPipeA`.

### P1-5: Blocking TLS Writes in Single-Threaded Event Loop
**File:** `bs_frame_io.hpp:51-61`
**Evidence:** `write_frame()` blocks up to `SO_SNDTIMEO` (10s) per peer. One slow consumer during gossip broadcast = `N × 10s` freeze.
**Fix:** Non-blocking sockets + per-connection write buffer deferred to next `select()` writable event.

## P2 — Quality & Scale

### P2-1: `select()` FD_SETSIZE Silent Drops
**File:** `bs_mesh.hpp:4158, 4182`
**Evidence:** fds ≥ 1024 silently excluded from select(). Connection stops being read, dies via pong timeout.
**Fix:** Migrate to `poll()` (no fd limit, portable).

### P2-2: Reconnect Backoff Lacks Jitter
**File:** `bs_mesh.hpp:3131-3134`
**Evidence:** Pure deterministic doubling. All peers reconnect simultaneously after daemon restart.
**Fix:** Add ±25% jitter to `delay_ms`.

### P2-3: Silent `catch(...)` in `connect_to_peer_impl`
**File:** `bs_mesh.hpp:1647`
**Evidence:** Swallows all exceptions including bad config (port parse errors). Zero diagnostic output.
**Fix:** `catch (const std::exception& e) { log_event("connect_failed", addr + " error: " + e.what()); return false; }`

### P2-4: No Session Persistence on Shutdown
**File:** `bs_mesh.hpp:4316`
**Evidence:** `run()` exits without calling `save_persisted_sessions()`. Session names/commands lost on restart.
**Fix:** Call `sessions_.save_persisted_sessions()` after event loop exits.

### P2-5: Legacy Unauthenticated TCP Port Still Active
**File:** `bs_mesh.hpp:3349-3443`
**Evidence:** Port 19980 accepts from any local user, leaks peer connectivity status.
**Fix:** Remove the listener entirely — `ipc2` supersedes it.

## USER FOCUS: Peer Name Resolution

**Current state:** `peer_name_eq` is exact-only case-insensitive match. No aliases, no fuzzy, no suggestions. User types `shadow` → silently fails if node is `windows-peer`.

**Live config has 4 "shadow" peers:** `shadow`, `windows-peer`, `shadow-df8uluc8`, `shadow-ph2lmg3f`. Typing `shadow` is genuinely ambiguous.

### Proposed: Three-Tier Resolution System (~250 LOC)

```
Tier 1: Exact case-insensitive (current, backward-compatible)
Tier 2: Config aliases (alias shadow windows-peer)
Tier 3: Suffix/prefix match (shadow → windows-peer)
Tier 4: Levenshtein ≤ 2 (shadwo → shadow)
```

- Single unambiguous fuzzy match → resolve + warn
- Multiple matches → list candidates, prompt if interactive
- No match → "Did you mean X?" + list all available peers

**Error messages redesigned per ConnectFailReason:**
- `refused` → "Is bridgesessions daemon running? Run: bs activate"
- `timeout` → "Check Tailscale/VPN. Try: ping <peer-ip>"
- `tls_rejected` → "Key mismatch. Re-authorize: bs invite / bs accept"
- `hello_rejected` → "Version incompatibility or authorization. Check: bs ctl logs"

### No-SSH-Fallback Contract

**Design invariant:** bs NEVER invokes SSH/WinRM/telnet. No code path exists for it.

Retry decision tree:
```
Transient (timeout/refused) → Retry 2x with backoff → Print diagnostics → EXIT
Permanent (tls_rejected/hello_rejected) → Print diagnostics → EXIT
NEVER → invoke ssh/winrm
```

## USER FOCUS: Command Stacking / Script Reuse

**Root cause identified:** Wire layer is escaping-safe (`AttachMsg.command` is length-prefixed binary). The breakage is entirely at Windows spawn:

```cpp
// bs_session.hpp:418 — THE BUG
std::string cmdline = "cmd.exe /c \"" + command + "\"";  // triple-nested quoting
```

**POSIX is fine** — `execl("/bin/sh", "-c", command)` passes script as single argv element.

### Proposed: `bs run-script <peer> <file>` (~80 LOC)

Composes existing `file_send` + `run_command` — zero new wire protocol:
1. Send script file to peer via existing file transfer
2. Execute by path (`powershell -File <path>` or `bash <path>`)
3. Script content never passes through shell quoting

**Additional proposals:**
- stdin/heredoc mode: `bs run-script peer - <<'EOF'`
- Content-addressed script cache: `bs script add/push/list` — SHA256-pinned library, fleet sync
- Interpreter-aware Windows spawn: don't wrap in `cmd.exe /c` when shell is `pwsh`

## Performance Notes

- **select() + blocking I/O** is the architectural ceiling (~20 peers max)
- **Ring buffer linearization** copies 1MB on every session attach — should scan backward in-place
- **Gossip** sends full peer snapshot to all connections every 30s — needs delta/versioning at scale
- **zstd** creates+destroys context per call — should use persistent `ZSTD_CCtx`/`ZSTD_DCtx`
- **No memory leaks** — all structures are bounded (discovered: 500 cap, conns: 50 cap, ring: 1MB fixed)
