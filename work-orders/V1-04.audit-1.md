## Nits (non-blocking)

1. **Internal jargon in a public README.** "operator / Admiral-gated" and
   "FECv3 / box installs" are internal operational names. The README itself
   warns against putting private host names in public material. Suggest
   generic wording (for example "maintainer-gated" and "some deployed nodes")
   before this reaches `main`.
2. **Time-sensitive statements.** "One-liner from `main` still defaults to
   26.09.28" and "`v26.10.04` … not published yet" stop being true the moment
   `release/26.10.04` merges to `main` or the Release is published. The tag
   was created at 23:14 CEST tonight, so a publish may be close. Whoever
   publishes must refresh these Status rows and `docs/index.md` at the same
   time.
3. **Receipt field naming.** In attempt-1, `diff_sha256` actually holds the
   sha256 of the post-change **file contents**. The values match the files at
   `2b77b5b`, but they are not diff hashes. The self-hash
   (`c705a226…`) was stale by construction. The attempt was updated with
   audit fields in this commit.
4. **"What is proven" row removed and not replaced.** The old 604/604 ctest
   claim was stale. `TODO-2026-10-04.md` now records Linux 632/632 and macOS
   630/630 CTest. A short, dated "tests" row would keep positive evidence.
   Optional.
5. **Stale TODO header (out of scope).** `TODO-2026-10-04.md` line 5 still
   says "No `v26.10.04` tag or release exists yet". The tag now exists. The
   builder flagged this correctly and did not edit it. Follow-up only.
6. The Windows (PowerShell) install subsection has no explicit default-tag
   note like the Linux one. The Status table covers `irm`, so this is minor.
