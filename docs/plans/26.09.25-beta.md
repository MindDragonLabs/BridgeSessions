## 6. Auto-update

Current behavior is not safe to trust.

- `mesh.auto_upgrade` defaults to true (`bs-config.h`). Live fecv3 config sets `mesh.auto_upgrade true` and `mesh.auto_upgrade_origin fecv3`.
- Cooldown is 3600 seconds when the key parses. A bad origin or a rejected pin can still retry much faster. The skill notes a rejected seed dial at about 1 per second.
- Windows in-band upgrade has already installed a file whose hash is not the GitHub asset.

Strategy:

- One origin is allowed to offer an upgrade. Other peers do not offer one.
- Download and verify `SHA256SUMS` before the daemon stops.
- Refuse the swap if the new file hash is not the published hash for that version string.
- Back off after a failed offer: 60 seconds, then 5 minutes, then the normal cooldown. Never 1 second.
- A failed swap restores the previous binary and leaves the service running.
- Prove it on one Linux canary, then one Windows host through WinRM, then one Mac. A crash or a retry faster than 10 seconds fails the proof.

Done when the canary log shows one successful swap, one forced bad-hash refusal, and no retry faster than 10 seconds.
