## 5. Blockers before integrating operator changes

### Terminal rendering

bs-tui.h counts bytes in tui_visible_len and code points in tui_truncate.
Neither measures terminal cells. Use one model for measurement, truncation, and
padding. Preserve UTF-8 boundaries and validate complete sequences in tests.

Acceptance: ASCII, accents, CJK, combining characters, supported emoji behavior,
colored labels, supported escape sequences, tiny widths, short heights, long
session lists, and resize while the menu is open. A real built binary under a
PTY must prove arrows, selection, cancellation, and terminal restoration.

Check direct menu_frame callers for small-width unsigned subtraction. Do not
claim support for every terminal size from a width-only clamp.

### Login-shell launch

The Linux profile/PATH fixture passes. Verify daemon-style environments on Linux
and macOS. Check profile output/errors, slow startup, command exit status,
worker/fallback paths, and unchanged Windows behavior. One shell fixture does
not prove all user's startup files are honored on every POSIX platform.

### Version handling

Do not push installer defaults referencing an unpublished release. Do not
silently revert the operator's VERSION edit. Record the current mismatch while
preparing the candidate. After release go, align VERSION, installer defaults,
Windows resources, and bundle metadata within the controlled train. Require
both parity tests to pass before shipping. Avoid a public-main window pointing
installers at absent assets.

## 6. Auth and transport decision

Mesh invites authorize mesh peers. Native-app credentials authorize API clients.
A phone must not receive full mesh access merely to use chat, sessions, or files.
The old panel work is input to this decision, not a completed mobile design.

Review before reuse:

- Cookies have HttpOnly and SameSite=Lax but no Secure attribute.
- Login reads Content-Length without an explicit request-size cap and assumes
  parsed JSON is an object.
- Credential reset keeps the signing secret and clears only the calling process's
  session map. A CLI reset leaves existing server sessions valid.
- Invalid credential configuration makes login_enabled false. Define fail-closed
  behavior instead of silently changing authorization modes.
- URL tokens can persist in browser history, copied URLs, and intermediary logs.
- Cookie sessions also satisfy require_token checks, including invite management.
  Define explicit administrative scope; do not grant mesh-enrollment access to
  every native-app login.
- Review origins, cookie-based writes, CSRF behavior, concurrent login attempts,
  brute-force controls, and resource limits. A short sleep is not a rate limit.
- Correct the module description: the implementation uses PBKDF2, not scrypt.

Recommended direction: retain loopback binding and an existing tailnet HTTPS
path; add no public service. Use scoped per-device API credentials with explicit
enrollment, revocation, expiry, and audit events. Write the decision record before
freezing the contract. Do not change security settings during this review.

## 7. Native-app phase 0 — original goals retained

Restore the shared C++ core skeleton and macOS-first shell omitted by the first
draft. Keep five native shells: Win32, AppKit, Linux, UIKit, and an Android NDK
boundary. Reuse the existing minimal dependency family. Apps speak only to
BridgePanel, not the mesh protocol.

### Gate A: capability and trust inventory

Map each operation to an implementation, stub, or missing primitive. Include
local/remote behavior, authorization, errors, timeouts, cancellation, and limits.
Write the transport/device-authorization decision before freezing the API.

Current evidence:

- tools/bridgepanel/api.py:229 returns wired:false for session input.
- tools/bridgepanel/api.py:280 returns remote metadata, not actual scrollback.
- Session creation uses a CLI subprocess. Review binary selection and failure
  behavior before promoting it to a stable API primitive.
- No /api/v1 implementation or agent-chat adapter was found in reviewed code.

### Gate B: one real backend vertical slice

Use an isolated test session. Through BridgePanel alone, select a remote session,
send a unique marker, and retrieve actual output incrementally. Prove a second
session does not receive it.

Trace the existing attached-shell path before deciding on new daemon IPC or
protocol work. Add a new primitive only when the inventory proves it necessary.

Pass conditions: authorized local/remote input reaches the intended session;
readback contains emitted bytes, not metadata; offsets/reset behavior are defined;
unauthorized and cross-session actions fail; timeouts, disconnect/reconnect,
stale names, and output bounds behave predictably. Do not probe a production
agent session without approval.

### Gate C: chat and files

Define an agent adapter with request identity, reply lifecycle, cancellation,
errors, and isolation. Prove it against a fixture, then an approved live agent.
Terminal typing alone is not a completed agent-chat API.

Prove file listing, bounded download, and permitted upload end-to-end. Validate
paths, allowed roots, limits, checksum/readback, and permission denials. Do not
widen sensitive-path access to make a test pass.

### Gate D: /api/v1 and native-client proof

Write the specification against proven capabilities. Define stable identifiers,
errors, streaming, pagination, discovery, versioning, and compatibility.
Create the shared C++ client core and build the macOS shell first. Prove an
authenticated session round-trip through BridgePanel.
Record Linux toolkit, Android glue boundary, minimum OS/architecture, and signing
decisions within phase 0. Do not defer them without an explicit scope decision.
