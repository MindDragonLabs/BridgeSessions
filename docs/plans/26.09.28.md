## Release train (on operator go)

1. `VERSION` → `26.09.28`; installer default tags → `26.09.28` (CI
   `test_default_tag_matches_version_file` enforces the match). Commit.
2. CHANGELOG 26.09.28 section finalised; README status block updated. Commit.
3. Build: Linux x86_64 (docker static), Windows x86_64 (MinGW), macOS arm64
   (macmini, ad-hoc sign per fleet practice).
4. Tag `v26.09.28` locally at HEAD → `package-release.sh --release` →
   `release-checksums.sh` → push main + tag → `scripts/github-release.sh`
   (auto-marks `-suffix` versions as prerelease) → verify `isPrerelease` and
   a fresh download's hash matches SHA256SUMS.
5. Fleet roll per policy: Linux lane, macOS lane (with the .app fix verified),
   Windows lane via WinRM hash-verify flow.
6. Verify: fresh download matches SHA256SUMS; `bs --version` prints 26.09.28;
   `bs fleet` shows the fleet on 26.09.28.
7. Run the e2e fleet matrix against the FINAL published binaries
   (`--json` result file required; mandatory gates must PASS, not SKIP;
   explicit Linux/macOS/Windows coverage).

## Hard limits (carried)

- No push of a VERSION bump before the publish — the public installer
  (`curl | bash`) resolves the default tag; a missing tag 404s the installer.
- Do not roll the fleet without the explicit operator go.
- Windows proof uses WinRM; `bs shell` is not the Windows proof.
